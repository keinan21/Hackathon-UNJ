# ibu-ibu-warung-polish - Work Plan

## TL;DR (For humans)
- **What you'll get**: aplikasi jadi ramah ibu-ibu warung — tombol Saran Tebus yang mati dihidupkan (klik → usulan promo + toast), menu **Catat** universal + halaman Keluar ala kasir (cari → +/− → total → Simpan Terjual), form Masuk 3-field + kalender + Tanpa-kadaluarsa, Threshold angka diganti preset 🥛📦🌾 (tanpa kata "Threshold"), cegatan harga rugi, scan anti-mulet, Backup 2 tombol, font ≥16px, istilah warung (Barang/Modal/Tumpukan).
- **Why this approach**: 5 wave / 19 task urut dependensi, tiap task = 1 branch `feat/ibu-*` + 1 worktree + 1 reviewer + CI hijau + squash (hormati AGENTS.md GitHub Flow). Temuan kritis Metis dipaksa sembuh dulu: kasir wajib reuse transaksi FEFO `OutboundForm` (bukan repo baru), preset wajib petakan 6 nilai seed eksisting, Catat hanya FAB+header (bottom-nav tetap 3-tab, tabel 3-tap design.md diamandemen).
- **What it will NOT do**: tidak tambah backend/Supabase; tidak ada Telegram rekap/pairing-AI baru/grafik baru/OCR/QR-generation/WA-send; tidak ubah lifecycle promo `proposed→active→expired/consumed`; tidak ubah `daysToExpiry` Asia/Jakarta startOfDay+ceil; tidak preload `html5-qrcode` di luar `/scan`; tidak tambah bottom-tab ke-4.
- **Effort**: 19 implementation todos + 4 final verifiers, 5 wave (Saran+guardrail → Catat+kasir → Scan+Settings → Copy+token → Gate).
- **Risk**: kasir multi-row vs FEFO single-SKU (mitigasi: reuse transaksi `dexieV2.transaction rw batches,transaksis`, 1 worktree Crew B); preset vs 6 nilai seed (mitigasi: mapping nearest-preset display-only, nilai tidak diubah paksa); tabrakan nav (mitigasi: FAB+header saja, Crew A pegang nav).
- **Decisions**: istilah full-warung (Barang/Modal/Tumpukan/Batas Ingat/Balik Modal/Peringkat/Arus Kas/Jumlah) • cegatan rugi = dialog konfirmasi `[Batal]/[Yakin Simpan]` • tanggal = native `type=date` + checkbox Tanpa-kadaluarsa→null • Backup tetap PIN-field tapi 2 tombol + bahasa jelas • tests-after + QA agen per todo.

## Scope
IN:
- Wave 1: Saran Tebus hidup (guardrail-before-create via `validatePromoUsul`, status `proposed`, scroll+toast+histori) + cegatan harga rugi (confirm dialog) + HPP-timpa confirm delta + Ubah Harga wiring.
- Wave 2: tombol Catat FAB+header + chooser Masuk/Keluar (tanpa tab ke-4, amandemen `docs/design.md` tabel 3-tap) + Masuk simpel + Keluar kasir reuse FEFO + seed preset mapping 6 nilai.
- Wave 3: Scan timeout 8s + fallback jelas + gate `?seed` bypass ke DEV + Settings Backup 2 tombol + Threshold preset selector (4 preset + manual collapsible).
- Wave 4: terminology sweep 38 strings + font 16px sweep (`text-[12px]|text-[13px]` → 0 untuk info penting) + toast seragam + `Qty`→`Jumlah` + `batch`→`tumpukan` di empty.
- Wave 5: Gate — build+PWA+offline+backup-roundtrip+PIN-lockout acceptance, `grep backend` 0.
OUT / Must-NOT-Have:
- Must NOT tambah backend, Supabase, Firebase, multi-role, POS payment, OCR, QR generation, WA send.
- Must NOT sentuh Telegram `telegramQueue` / `fetch api.telegram.org` (allowlist ADR-003 hanya notif).
- Must NOT preload `html5-qrcode` di luar `/scan` (tetap `lazy` di `App.tsx:19`).
- Must NOT ubah lifecycle promo `proposed→active→expired/consumed` (`src/db/types.ts:69`).
- Must NOT ubah `daysToExpiry` Asia/Jakarta startOfDay + ceil.
- Must NOT biarkan LLM hitung angka — angka dari DB/engine, LLM hanya wording+pairing.
- Must NOT tambah bottom-tab ke-4 — Catat hanya FAB + header.
- Must NOT bikin repo/FEFO kedua untuk kasir — reuse transaksi `OutboundForm`.
- Must NOT paksa ubah nilai threshold eksisting saat migrasi preset (display nearest-preset saja).
- Must NOT commit token/plaintext secret — enkripsi PBKDF2+AES-GCM via `src/lib/crypto.ts`.

## Verification strategy
- Tests-after: tiap todo punya `bun test` dan/atau `npx playwright test` agent-executable (happy + failure), evidence di `.omo/evidence/ibu-<nn>-*.(json|png|log)`, disync di PR yang sama.
- Gate per-PR: `bun run build` exit 0 + `dist/manifest.webmanifest` + `dist/sw.js` ada; `bun test` hijau; `npx playwright test` untuk todo e2e; `grep -r "supabase|firebase" src` 0; `grep -R "text-\[12px\]|text-\[13px\]" src` 0 untuk info penting.
- Final wave F1-F4 paralel, semua APPROVE sebelum handoff.

## Execution strategy
- 5 wave berurutan; tiap todo = 1 branch `feat/ibu-<slug>` dari main terbaru + 1 worktree + 1 PR + 1 reviewer + CI hijau + squash merge (AGENTS.md GitHub Flow).
- Ownership (AGENTS.md): Crew A → nav/FAB/Katalog/copy/token/promo-UI; Crew B → SkuForm/db/Inbound/Outbound/kasir/seed (1 worktree untuk C2a/b/c); Crew D → Scan/App-shell/Settings/Backup; Crew C → reuse validasi `src/lib/validation.ts` saja.
- Dependency: W1 DONE → W2 urutan 20 (saran shared+kritis), 21 (/promo+/statistik+info-mode), 5 (hub assembly, butuh 21), 6, 7 (kasir = target tombol Kasir), 8 → W3 (butuh preset mapping todo 8) → W4 (butuh semua string final W1-W3) → W5 gate. Dalam wave boleh paralel jika file tidak tabrakan (dicatat per todo).
- Worker mulai via `$start-work ibu-ibu-warung-polish` (opsi `--make-pr` per wave).
