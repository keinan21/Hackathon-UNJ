# Plan Perbaikan UX Kasir (Tanpa Fitur Baru)

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Kasir existing jadi ramah kasir warung tanpa tambah fitur: bahasa warung, error jelas, FTUE tidak bingung, zona jempol aman.

**Architecture:** Ubah copy + state UI di `KasirPage` saja; nama kategori tampil via peta alias display-only (DB, threshold, kode SKU tidak berubah); logika FEFO `src/db/keluar.ts` tidak disentuh.

**Tech Stack:** React + TypeScript + Tailwind/daisyUI, Dexie via `realRepo`, vitest + Playwright.

**Keputusan terkunci (grill 3 ronde, 2026-09-12):** tanpa langkah bayar, tanpa struk, tanpa promo di kasir, harga kaku, route tetap `/keluar`, alias tampil saja, Misc jadi Lain-lain, Makanan Basah tetap + contoh, Frozen jadi Makanan Beku, Obat Bebas jadi Obat dan Kesehatan, Perawatan Diri tetap + contoh, loading kartu bayangan, tombol "Mulai jualan baru", tombol akhir "Selesaikan Jualan".

---

## Batasan scope (MUST NOT)

- MUST NOT tambah input uang/kembalian, struk, promo di kasir, diskon/edit harga.
- MUST NOT tambah tabel/kolom DB, ubah threshold angka, ubah logika FEFO, ganti route.
- MUST NOT ubah nama kategori di DB (hanya alias tampil). Kode SKU prefix (`MSC` dll) tetap.
- Bahasa Indonesia, tombol min 48px, font min 16px, kontras AA (guardrail `docs/design.md` + `AGENTS.md`).

**Files:**

**Step 1: Tulis test gagal**

```ts
import { describe, test, expect } from "vitest";
import { namaTampilKategori, contohKategori } from "./kategoriTampil";

describe("namaTampilKategori", () => {
  test("Misc tampil sebagai Lain-lain, DB tidak berubah", () => {
    expect(namaTampilKategori("Misc")).toBe("Lain-lain");
    expect(namaTampilKategori("Makanan Frozen")).toBe("Makanan Beku");
    expect(namaTampilKategori("Obat Bebas")).toBe("Obat dan Kesehatan");
    expect(namaTampilKategori("Sembako")).toBe("Sembako");
    expect(namaTampilKategori("Kategori Asing")).toBe("Kategori Asing");
  });
  test("setiap kategori seed punya contoh", () => {
    expect(contohKategori("Misc")).toContain("baterai");
    expect(contohKategori("Makanan Basah")).toContain("tempe");
  });
});
```

**Step 2: Run, expected FAIL**

Run: `bun test src/lib/kategoriTampil.test.ts`
Expected: FAIL — modul belum ada.

**Step 3: Implementasi minimal**

```ts
const ALIAS: Record<string, string> = {
  "Misc": "Lain-lain",
  "Makanan Frozen": "Makanan Beku",
  "Obat Bebas": "Obat dan Kesehatan",
};
const CONTOH: Record<string, string> = {
  "Sembako": "beras, minyak, telur",
  "Bumbu Dapur": "garam, gula, kecap",
  "Makanan Kering": "mi instan, biskuit",
  "Makanan Basah": "tahu, tempe, ayam",
  "Makanan Frozen": "nugget, sosis",
  "Minuman Kaleng": "soda kaleng",
  "Minuman Botol": "teh botol, air mineral",
  "Obat Bebas": "plester, vitamin",
  "Perawatan Diri": "sabun, sampo",
  "Rokok": "per bungkus",
  "Misc": "plastik, baterai",
};
export function namaTampilKategori(nama: string): string { return ALIAS[nama] ?? nama; }
export function contohKategori(nama: string): string { return CONTOH[nama] ?? ""; }
```

**Step 4: Run, expected PASS**

Run: `bun test src/lib/kategoriTampil.test.ts`
Expected: PASS.

```bash
git add src/lib/kategoriTampil.ts src/lib/kategoriTampil.test.ts
```

### Task 4: State loading, empty CTA, sukses lanjutan, fokus error, safe-area

**Objective:** R-27 patuh (loading vs kosong vs error), FTUE jelas, jempol aman. Semua UI-only.

**Files:**
- Modify: `src/features/inout/KasirPage.tsx`

**Langkah:**
1. State `loading`: `true` saat `loadRows` jalan. Saat loading render 3 kartu skeleton berdenyut (`aria-busy`, `data-testid="kasir-loading"`). Empty state + CTA hanya jika `!loading && rows.length === 0`.
2. Empty CTA: tombol "Tambah Barang" 48px (`data-testid="kasir-empty-cta"`) → `/sku/baru` via `pushState` + `popstate` (pola existing).
3. Sukses: di bawah pesan sukses render tombol outline "Mulai jualan baru" (`data-testid="kasir-baru"`) → fokus ke `kasir-search` (cart sudah kosong seperti sekarang).
4. Error: baris salah dapat border merah (kelas existing `border-[#FFCDD2]`/`text-[#C62828]`); setelah validasi gagal, fokus otomatis ke input qty baris salah pertama.
5. Sticky bar tambah `paddingBottom: max(0px, env(safe-area-inset-bottom))` mengikuti pola `App.tsx:315`.

**Verifikasi:** Playwright: throttling tidak perlu; assert `kasir-loading` muncul sesaat lalu hilang; empty-DB tampil CTA; overstock tampil pesan baru + fokus di input qty baris pertama; mobile 360px tidak overlap bottom nav.

## Risiko dan tradeoff

- Alias vs rename: dipilih alias agar nol migrasi; konsekuensi nama DB tetap teknis di export/backup mentah (diterima, di luar scope).
- Angka "Stok: X" tetap total semua batch (bukan FEFO-available) demi prinsip tanpa-perubahan-logika; ketidakjujuran sisa vs bisa-jual ditutup via pesan error yang menyebut nama + sisa, bukan via ubah angka.
- `seed.test.ts` / `seed-race.test.ts` yang expect nama "Misc" tidak perlu diubah karena DB tidak berubah.
